# سامانه ثبت و رهگیری OKR — دپارتمان محصول و تکنولوژی

وب‌اپلیکیشن داخلی و **کاملاً self-hosted** برای تعریف، ثبت و رهگیری هفتگی OKRهای هفت تیم دپارتمان
(ورزشی، تماشا، پیام‌رسان، کلاسا، عملیات/CRM، تکنولوژی، بینش داده) — بدون هیچ وابستگی به سرویس ابری.

- رابط کاربری: فارسی و راست‌به‌چپ (فونت وزیرمتن، self-hosted)
- تاریخ‌ها: شمسی/جلالی (کتابخانه `jalaali-js`)
- استک: Next.js 14 (App Router, TypeScript) + Prisma + PostgreSQL + NextAuth (Credentials) + Tailwind + Recharts + SheetJS

## راه‌اندازی سریع با Docker (پیشنهادی)

```bash
cp .env.example .env
# مقدار NEXTAUTH_SECRET را عوض کنید: openssl rand -base64 32
# روی سرور، NEXTAUTH_URL را به آدرس داخلی سرور تغییر دهید (مثلاً http://okr.internal.mci)

docker compose up -d --build
```

همین! کانتینر `app` هنگام بالا آمدن، خودش اسکیمای دیتابیس را اعمال (`prisma db push`) و seed اولیه را اجرا می‌کند.
اپ روی `http://localhost:3000` در دسترس است.

برای فعال‌کردن nginx به‌عنوان reverse proxy روی پورت ۸۰:

```bash
docker compose --profile proxy up -d
```

## اجرای لوکال بدون Docker (توسعه)

```bash
# ۱) فقط دیتابیس را با Docker بالا بیاورید
docker compose up -d postgres

# ۲) وابستگی‌ها و دیتابیس
cp .env.example .env
npm install
npx prisma db push
npm run db:seed

# ۳) اجرا
npm run dev
```

## قابلیت‌ها

### پنل مدیریت (ADMIN — وحید عامری و جلیل علیزاده با دسترسی برابر)
- **داشبورد ویژوال**: پیشرفت وزنی دپارتمان با دلتای هفتگی (هنگام هاور)، کارت‌های آماری وضعیت کلیک‌پذیر، دونات توزیع وضعیت KRها، روند هفتگی، لیدربورد تیم‌ها، تقویم شمسی با بازه‌ی چک‌این و نوار زمانِ سپری‌شده/باقی‌ماندهٔ دوره، و کارت هر تیم با حلقه‌ی درصد و اسپارک‌لاین و drill-down.
- **تعریف/ویرایش OKR (ویزارد چهارمرحله‌ای)**: مرحله ۱ هدف + انتخاب **تیم و وزن** (وزن هدف همان وزن تیم است، بازهٔ ۰ تا ۱۰۰)، مرحله ۲ تیم‌های مشترک با وزن هرکدام، مرحله ۳ نتایج کلیدی (بدون انتخاب تیم — از هدف به ارث می‌رسد)، مرحله ۴ بازبینی. برای نوع «بله/خیر» تارگت هم انتخاب می‌شود (بله یا خیر).
- **آپلود اکسل**: پارس با SheetJS، پیش‌نمایش کامل قبل از تأیید، گزارش خطای ردیف‌های نامعتبر، فایل نمونه قابل دانلود از خود صفحه.
- **خروجی‌ها** (زیرمنوی «تنظیمات و پیکربندی»): Excel دوشیتی، گزارش چاپی PDF، و **خروجی تفکیک‌شده‌ی هر دیتاست (چک‌این‌ها، OKRها، تیم‌ها، کاربران) در سه فرمت CSV / JSON / Markdown**.
- **گزارش‌های هفتگی**: مرور چک‌این‌های هفتگی همه‌ی تیم‌ها + کامنت‌گذاری، در نمای کارتی/جدولی.
- **مدیریت کاربران**: ایجاد/غیرفعال‌سازی، تعیین نقش و تیم(ها)، ریست پسورد موقت، مشاهده‌ی تاریخچه‌ی نشست‌ها (ورود/خروج، IP، مرورگر).
- **منوی دسته‌بندی‌شده**: موارد پیکربندی (تعریف دوره‌ها، آپلود اکسل، خروجی‌ها، کاربران، تنظیمات) زیر گروه بازشوی «تنظیمات و پیکربندی» قرار دارند.

### پنل تیم (TEAM_MEMBER) — چهار بخش
- **داشبورد**: نمای کلی تیم شبیه داشبورد دپارتمان — کارت‌های وضعیت (کلیک‌پذیر با فیلتر)، روند هفتگی، تقویم با نوار زمان دوره، پیگیری چک‌این این هفته، بلاکرهای فعال، و لیدربورد.
- **OKRهای من**: فهرست کامل نتایج کلیدی تیم با ثبت/ویرایش چک‌این و گفتگو، در دو نمای **کارتی یا جدولی**.
- **ثبت وضعیت هفتگی**: عددی (با نمایش هزار/میلیون)، بله/خیر، یا محتوایی + وضعیت پیشرفت + توضیح بلاکر + ضمیمه. ثبت مجدد در همان هفته، مقدار قبلی همان هفته را به‌روزرسانی می‌کند (upsert بر اساس شنبه‌ی شروع هفته‌ی شمسی) و پس از ثبت، دکمه‌ی جدا برای «ویرایش/به‌روزرسانی» فعال می‌شود.
- **خلاصه وضعیت**: نمای فشرده‌ی سلامت اهداف، چک‌این‌های مانده و بلاکرها.
- کاربر عضو چند تیم (مثل علیرضا یحیایی) با سوییچر بالای صفحه بین تیم‌هایش جابه‌جا می‌شود.
- ابزار مدیریتی لید: «موارد باقی‌ماندهٔ چک‌این این هفته» مستقیم به همان KR در صفحهٔ ثبت لینک می‌شوند.

### تنظیمات کاربری و یادآوری پوش
- هر کاربر با کلیک روی نام خودش در نوار بالا به **تنظیمات کاربری** می‌رود: تغییر رمز (نام کاربری ثابت می‌ماند)، مشاهده‌ی ورودهای اخیر، و فعال‌سازی یادآوری.
- **پوش نوتیفیکیشن یادآوری چک‌این**: روزهای دوشنبه تا چهارشنبه، ساعت ۱۰ صبح تهران، اگر تیمی KR بدون چک‌این در هفته‌ی جاری داشته باشد، به اعضای مشترک‌شده‌ی آن تیم نوتیفیکیشن مرورگر ارسال می‌شود. کلیدهای VAPID خودکار تولید و در دیتابیس نگه‌داری می‌شوند (بدون سرویس خارجی).
- ⚠ محدودیت مرورگرها: پوش نوتیفیکیشن فقط روی **HTTPS** (یا localhost) کار می‌کند. برای استفاده روی سرور داخلی، پشت nginx یک گواهی TLS داخلی بگذارید.

### قابلیت‌های مدیریتی تکمیلی
- **تاریخچه‌ی تغییرات OKR** (منوی «تاریخچه تغییرات»): هر تغییر ادمین در هدف/KR/سهم تیمی (وزن، تارگت، حداقل و...) با فیلد، مقدار قبلی/جدید، زمان و کاربر ثبت می‌شود.
- **قفل چک‌این‌های گذشته**: تیم فقط چک‌این هفته‌ی جاری را می‌تواند ثبت/به‌روزرسانی کند (سرور خودش هفته را تعیین می‌کند)؛ هفته‌های گذشته قفل‌اند.
- **لیدربورد ماهانه‌ی pacing**: رتبه‌بندی تیم‌ها بر اساس «پیشرفت واقعی − مورد انتظار» در داشبورد ادمین و پنل تیم (فقط‌خواندنی، بدون جزئیات OKR سایر تیم‌ها). پایان هر ماه شمسی خودکار در `MonthlyLeaderboard` اسنپ‌شات می‌شود.
- **بلاکر پایدار**: KRهایی که ۲ هفته‌ی متوالی یا بیشتر BLOCKED گزارش شده‌اند، در داشبورد و «خلاصه هفته» با تگ 🔁 برجسته می‌شوند.
- **خلاصه هفته** (منوی «خلاصه هفته»): گزارش خودکار قابل چاپ برای مدیر دپارتمان/مدیر برنامه — تیم‌های در مسیر/عقب، چک‌این‌های ثبت‌نشده، بلاکرهای باز.
- **مقایسه دوره‌ها**: جدول تیم × دوره با پیشرفت نهایی هر دوره برای مقایسه‌ی فصل‌به‌فصل.
- **آستانه‌های قابل تنظیم** (منوی «تنظیمات»): اعداد وضعیت خودکار (جلوتر/در ریسک/عقب‌افتاده) از پنل ادمین قابل تغییرند و در `AppSetting` ذخیره می‌شوند — بدون نیاز به تغییر کد.

## مدل داده و KRهای مشترک

رابطه‌ی Team↔KeyResult از طریق جدول واسط **`TeamKeyResult`** مدل شده که برای هر تیم:
`weight` (وزن اختصاصی)، `targetValueOverride` و `minValueOverride` دارد.
چک‌این‌های هفتگی (`WeeklyCheckIn`) به `TeamKeyResult` وصل‌اند نه به خود KR؛ یعنی هر تیم مستقل برای سهم خودش
ثبت می‌کند و پیشرفت دپارتمان از میانگین وزنی همه‌ی رکوردهای `TeamKeyResult` محاسبه می‌شود.

### نحوه‌ی محاسبه‌ی پیشرفت (فرض‌های مستندشده)
- **عددی (NUMERIC)**: `(مقدار فعلی − حداقل) ÷ (تارگت − حداقل)`، محدود به بازه ۰ تا ۱۰۰٪. override تیمی اولویت دارد.
- **بله/خیر (BOOLEAN)**: KR یک تارگت «بله» یا «خیر» دارد (`targetBoolean`). تیم می‌تواند KR را به **تسک‌های
  کوچک‌تر** (چک‌لیست) تقسیم کند؛ آن‌گاه پیشرفت = «تسک‌های انجام‌شده ÷ کل» محاسبه می‌شود. اگر تسکی تعریف نشده باشد،
  در چک‌این هفتگی حالت سه‌گانه انتخاب می‌شود: خیر=۰٪، در حال انجام=۵۰٪، بله=۱۰۰٪ (مقدار به‌عنوان مقدار آن هفته ذخیره می‌شود و روند حفظ می‌گردد).
- **محتوایی (TEXT)**: بر اساس وضعیت انتخابی: تکمیل‌شده=۱۰۰٪، در مسیر=۵۰٪، در ریسک=۲۵٪، بلاک‌شده=۰٪.
- پیشرفت تیم/دپارتمان = میانگین وزنی پیشرفت KRها با وزن‌های `TeamKeyResult`.
- هفته از **شنبه** شروع می‌شود (تقویم شمسی) و کلید یکتای چک‌این، (KR تیم، شنبه‌ی هفته) است.

### وضعیت زمانی خودکار (بدون قضاوت دستی)
علاوه بر وضعیتی که تیم دستی ثبت می‌کند، سیستم برای هر KR-تیم/تیم/هدف یک **وضعیت زمانی خودکار** محاسبه می‌کند:
- `پیشرفت مورد انتظار = زمان سپری‌شده از دوره ÷ کل مدت دوره` — دوره از رشته‌ی period پارس می‌شود
  (فرمت‌های `Q1-1405` تا `Q4-1405` برای فصل شمسی و `1405` برای کل سال؛ فرمت ناشناخته → محاسبه غیرفعال).
- `پیشرفت واقعی` همان پیشرفت وزنی محاسبه‌شده است (برای مایل‌استونی: انجام‌شده ÷ کل).
- اختلاف (واقعی − مورد انتظار): **+۵ به بالا = جلوتر از برنامه**، تا **−۱۰ = در مسیر**،
  تا **−۲۵ = در ریسک**، پایین‌تر = **عقب‌افتاده**. این تگ (⏱) در داشبورد، کارت تیم‌ها، جدول KRها،
  گزارش چاپی و خروجی Excel نمایش داده می‌شود.

## فرمت فایل اکسل ورودی

سطر اول هدر است؛ ستون‌ها (فایل نمونه از صفحه‌ی «آپلود اکسل» قابل دانلود است):

| ستون | توضیح |
|---|---|
| هدف | عنوان Objective — ردیف‌های هم‌عنوانِ هم‌دوره زیر یک هدف گروه می‌شوند |
| توضیحات هدف، وزن هدف | اختیاری (وزن پیش‌فرض ۱) |
| دوره | مثل `Q2-1405`؛ خالی = فصل شمسی جاری |
| نتیجه کلیدی، وزن نتیجه کلیدی | عنوان و وزن پیش‌فرض KR |
| نوع سنجش | `عددی` / `بله/خیر` / `محتوایی` (خالی = عددی) |
| حداقل، تارگت، واحد | برای نوع عددی (تارگت الزامی) |
| توضیحات | اختیاری |
| تیم‌ها | نام تیم‌ها جداشده با «،» — بیش از یک تیم = KR مشترک |
| وزن تیمی | وزن هر تیم به همان ترتیب، جداشده با «،» (خالی = وزن KR) |
| تارگت تیمی | تارگت اختصاصی هر تیم به همان ترتیب (اختیاری) |

اعداد فارسی (۱۲۳) و جداکننده‌ی هزارگان در سلول‌ها پشتیبانی می‌شوند.

## دیپلوی روی سرور داخلی (MCI)

1. سورس را روی سرور کپی کنید (یا `git clone` از ریموت داخلی).
2. `cp .env.example .env` و مقداردهی:
   - `NEXTAUTH_SECRET`: خروجی `openssl rand -base64 32`
   - `NEXTAUTH_URL`: آدرس داخلی سرور، مثلاً `http://10.x.x.x` یا دامنه داخلی
   - پسوردهای Postgres را عوض کنید.
3. `docker compose --profile proxy up -d --build` (nginx روی پورت ۸۰).
4. داده‌ها در volume داکری `postgres_data` می‌مانند. بکاپ:
   ```bash
   docker compose exec postgres pg_dump -U okr okr_tracker > backup-$(date +%F).sql
   ```

هیچ متغیر محیطی به سرویس خارجی اشاره نمی‌کند؛ فونت، کتابخانه‌ها و دیتابیس همگی داخل ایمیج/کانتینرند.

## امنیت (استقرار روی سرور)

- **هدرهای امنیتی** روی همه‌ی مسیرها: `X-Content-Type-Options: nosniff`، `X-Frame-Options: SAMEORIGIN`، `Referrer-Policy`، `Permissions-Policy` و حذف `X-Powered-By`.
- **ضمیمه‌ها**: آپلود فقط با نوع مجاز (PNG/JPG/PDF/DOCX)، حداکثر ۳ فایل و ۱۰ مگابایت؛ دانلود با `Content-Disposition: attachment` + `nosniff` و کنترل دسترسی تیمی.
- **رمزها**: با `bcrypt` هش می‌شوند؛ نشست‌ها JWT با انقضای ۱۲ ساعت.
- **حتماً قبل از استقرار**: `NEXTAUTH_SECRET` قوی (`openssl rand -base64 32`) و `POSTGRES_PASSWORD` غیرپیش‌فرض بگذارید. اگر ضعیف باشد، هنگام بالا آمدن در لاگ هشدار داده می‌شود. برای HTTPS از پروفایل `proxy` (nginx) استفاده کنید تا کوکی‌ها `Secure` شوند.

## فرض‌های منطقی

- خروجی PDF از طریق صفحه‌ی گزارش چاپی + Print مرورگر انجام می‌شود تا وابستگی باینری/سرویس خارجی اضافه نشود.
- ادمین‌ها در پنل تیم به همه‌ی تیم‌ها دسترسی دارند (برای ثبت جایگزین در صورت نیاز).
- لاگ خروج نشست فقط هنگام «خروج» صریح ثبت می‌شود؛ انقضای توکن (۱۲ ساعت) به‌صورت «باز/نامشخص» نمایش داده می‌شود.
- حذف هدف/KR به‌صورت cascade چک‌این‌های مرتبط را هم حذف می‌کند (با تأیید دومرحله‌ای در UI).
